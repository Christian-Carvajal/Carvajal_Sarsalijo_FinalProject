Project Overview & Business Scenario
Perpetual Bistro, the campus dining facility at UPHSD, seeks to modernize its 
customer service experience by deploying a table-side digital waiter. The 
system must run 100% locally (zero cloud dependencies) using Ollama (Qwen 
2.5), Python, SQLite, and STT/TTS Speech Modules.
The AI Virtual Waiter serves as an interactive, voice-enabled, state-aware 
ordering assistant. Customers converse naturally—asking about menu 
ingredients, requesting customizations (e.g. "Make it spicy, no onions"), 
checking dietary restrictions, and managing their active order tab. The 
system must dynamically bind spoken or typed user intents to local SQLite 
tool functions, update real-time kitchen inventory, enforce strict Finite State 
Machine (FSM) state transitions, and generate a final itemized receipt upon 
checkout.

1. The I/O Surface Layer (Top Box)
This is the external boundary of the system that interacts directly with the 
customer at the table.
• Speech-to-Text (STT) Microphone: Listens to physical room audio and 
transcribes spoken customer requests into plain text strings.
• Text-to-Speech (TTS) Speaker: Takes plain string responses generated by 
the AI agent and synthesizes them into spoken vocal audio for table 
feedback.
• Web / CustomTkinter UI Dashboard: Renders visual elements (food 
photos, prices, active cart line items, subtotal) and provides manual 
"human-in-the-loop" touch controls (+, -, Delete).

2. The Core Agent Engine (Middle Box)
This is the internal processing hub where conversation state, artificial 
intelligence reasoning, and intent execution converge.
• FSM State Controller (Left Sub-Block):
oActs as the unbypassable guardrail enforcing valid business flow (GREETING →
ORDERING →REVIEW →CONFIRMED).
o Prevents state-skipping (e.g., blocking order checkout if the cart is empty or 
rejecting post-confirmation modifications).
• Local Ollama / Qwen 2.5 Engine (Right Sub-Block):
o Receives natural language text strings from the user alongside the current state 
context.
o Evaluates user intent (e.g., "Add 2 Cheeseburgers with extra pickles") and outputs 
structured JSON function calls matching local database tools.

3. The Relational Persistence Layer (Bottom Database Box)
This serves as the single source of truth for the entire application.
• Menu & Stock Inventory (menu_items): Stores item names, descriptions, 
prices, dietary flags, food photo paths, and real-time inventory counts 
(stock_qty).
• Active Cart (cart_items): Tracks line items, quantities, and special 
instructions added during the active session.
• Table Sessions (table_sessions): Maintains table numbers, creation 
timestamps, and active state machine stages.
• Architectural Role: All tool executions emitted by Qwen directly query or 
mutate this database via transactional SQLite CRUD functions 
(db_tools.py). Programmatic inventory guards inside Python check 
stock_qty before executing commits to guarantee data integrity.

Why This Design Is Robust for each group?
• Isolation of Failures: If the microphone stream or TTS voice driver fails, the 
backend FSM, database transactions, and Qwen tool calling continue 
running 100% reliably through the text dashboard.

(FSM + Qwen + SQLite) in Lesson 6 Lab via terminal text prompts before 
connecting the top I/O layer (STT/TTS and UI) for the Final Project.
