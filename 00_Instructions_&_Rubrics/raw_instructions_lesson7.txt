1. Business Scenario: 
Project Overview & Business Scenario 
Perpetual Bistro, the campus dining facility at UPHSD, seeks to modernize its customer service experience by deploying 
a table-side digital waiter. The system must run 100% locally (zero cloud dependencies) using Ollama (Qwen 2.5), 
Python, SQLite, and STT/TTS Speech Modules. 
The AI Virtual Waiter serves as an interactive, voice-enabled, state-aware ordering assistant. Customers converse 
naturally—asking about menu ingredients, requesting customizations ("Make it spicy, no onions"), checking dietary 
restrictions, and managing their active order tab. The system must dynamically bind spoken or typed user intents to 
local SQLite tool functions, update real-time kitchen inventory, enforce strict Finite State Machine (FSM) state 
transitions, and generate a final itemized receipt upon checkout.

Phase 2: Database Tooling & FSM State Machine (Oct 23 – Oct 25) 
Building backend logic and state controls 
1. Implement Database CRUD Wrapper (db_tools.py): Write Python helper functions for querying menu 
categories, calculating cart totals, and atomic stock subtractions: 
o 
get_menu_items(category) 
o 
add_item_to_order_tool(session_id, item_name, qty, instructions) 
o 
get_cart_summary(session_id) 
2. Construct FSM Controller (fsm_controller.py): Implement the state machine class to enforce strict dialogue 
states: 
o 
GREETING →Captures table number. 
o 
ORDERING →Processes tool calls for cart modifications. 
o 
REVIEW →Presents itemized cart and subtotal for customer verification. 
o 
CONFIRMED →Commits transaction and locks cart modifications. 
 
Phase 3: Decoupled Speech I/O Pipeline (Oct 26 – Oct 28) 
Milestone 1 Deliverable Checkpoint 
1. Build Speech Audio Wrappers (speech_engine.py): Implement input/output abstraction adapters: 
o 
Speech-to-Text (STT): Captures microphone audio using SpeechRecognition or whisper and converts to 
string text. 
o 
Text-to-Speech (TTS): Converts agent response strings to audio speech via pyttsx3. 
2. Milestone 1 Verification & Submission: Run CLI integration script to verify that a spoken input triggers an FSM 
state transition and updates SQLite without GUI dependencies. 
Milestone 1 Deadline: Wednesday, October 28, 2026 
Phase 4: Agentic Tool Calling & Guardrails (Oct 29 – Nov 02) 
Connecting Qwen 2.5 reasoning to database functions 
1. Define JSON Tool Specs for Qwen: Inject available function signatures into Qwen system prompts so the local 
model emits structured JSON for tool calls. 
2. Programmatic Inventory Guardrails: Enforce hard code guards inside db_tools.py so that if Qwen requests 5 
orders of Pan-Seared Salmon but stock is 2, the system blocks the commit and prompts Qwen to offer 
alternatives. 
3. Edge Case & Out-of-Domain Handling: Implement system prompt rules to politely reject off-topic questions 
(e.g., weather or general knowledge) and redirect the user back to ordering.
